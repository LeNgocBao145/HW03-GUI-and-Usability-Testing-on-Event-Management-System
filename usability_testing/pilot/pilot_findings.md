# Pilot Findings

## Problems in the Test Design

The protocol did not initially state whether post-task confirmation was inside time on task or define the exact endpoint for a pending registration. This could make durations inconsistent across moderators.

## Unclear Task Wording

The phrase "role that best describes you" could be interpreted as an account role, event duty, or attendee category. It was revised to "attendee role you would actually use."

## Broken Flow

No broken test flow was observed. However, the preflight checklist needed an explicit check that an upcoming event had open registration and a suitable role, otherwise a valid session could become impossible.

## Missing Moderator Instructions

The script did not explicitly tell the moderator to stop timing before SUS or how to separate neutral think-aloud prompts from task-directed help.

## Measurement Problems

The original protocol lacked a single stop rule. The revised rule stops timing when the participant identifies the resulting registration status or abandons the task.

## Technical Interruptions

None observed.

The pilot is excluded from main-session metrics.
